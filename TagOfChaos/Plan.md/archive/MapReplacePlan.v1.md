## 0. 요약

**할 수 있다. 다만 “이미 만든 FBX를 줄이는” 방식이 아니라, 맵을 만드는 Blender 스크립트의 배치 값을 바꿔 다시 생성해야 한다.**

- 맵 5개는 모두 `build_*.py`가 **코드로 생성**한다(맵 크기 `HALF = 175`, 도로·광장 반경, 건물 벽 길이, 산포 영역·개수, 언덕·그릇 좌표가 전부 스크립트 값).
  물체(에셋)는 `ASSETS`의 고정 모양 + `place(..., s)`의 배율로 놓이므로, **배치 값만 바꾸고 배율은 건드리지 않으면 “물체 크기 불변”이 자동으로 지켜진다.**
- 단순히 좌표만 0.3배로 줄이면(= 받은 NewMap FBX) 벽·작업대·기계가 서로 문을 막는다(부록 B). 그래서 **맵마다 배치를 새로 짠다**: 고정 크기 랜드마크는 유지하고,
  건물(절차 생성 벽)은 들어가는 내용물 + 괴물 통로 기준으로 다시 치수를 정하고, 산포 개수는 면적에 맞춰 줄이고, 들어가지 않는 시설은 뺀다.
- **“못 지나가는 곳 없음”을 규칙(§2)과 자동 검사(§6)로 보장한다.** 규칙은 이미 스크립트에 있는 괴물 기준(문·실내 통로 폭·높이 7 m, `maplib.py:712-713`)을
  바탕으로, 이번에 “애매한 틈 금지”(걷는 높이의 틈은 0.3 m 이하로 막히거나 4 m 이상 열림)를 더한다.
  검사는 Blender(기존 `door_report`·`door_sweep`)와 Unity(신규 통과성 검사 — 실제 프리팹 크기)의 두 단계로 하고, 하나라도 실패하면 맵을 완료로 보지 않는다.
- 목표 크기: **한 변 105 m(경계 ±52.5 m, 70% 축소)**. 75%(87.5 m)는 빵집의 마법 오븐(폭 46 m, 고정)과 괴물 통로 7 m를 넣으면 건물 밖 공간이 거의 남지 않아 권장하지 않는다(§9 Q1).

면적은 약 1/11(122,500 m² → 11,025 m²)이 된다. 따라서 **내용물도 약 1/10로 줄어든다.** 랜드마크 5개는 모두 유지하지만, 놀이공원의 대형 서커스 천막(44 m)·범퍼카장,
초콜릿공장의 바깥 사분면 건물 4동과 강, 빵집의 복도·사일로 마당은 빠진다(§5, 결정 §9 Q3).

## 3. 방법

### 3.1 왜 FBX를 줄이지 않고 스크립트를 고치는가

| 방법 | 결과 |
|---|---|
| FBX(또는 씬) 좌표를 0.3배 | 받은 NewMap과 같다 — 물체 크기는 그대로인데 간격만 줄어 **벽이 서로의 문을 막는다**(상인방 50곳 중 12곳 중앙 막힘, 공장 바닥 23% 고립). 벽이 여러 조각이라 조각끼리 겹친다 |
| FBX 전체를 0.3배 | 물체도 0.3배 — R1 위반(쿠키보다 작은 집) |
| Unity 빌더가 자동으로 물체를 밀어내기 | 벽처럼 “구조물끼리 겹친 곳”은 밀어낼 대상이 없고, 원본과 씬이 어긋나 재출력 때 다시 생긴다 |
| **스크립트 배치 값 수정 + 재생성**(채택) | 벽은 새 길이로 다시 만들어지고 문(`wall(gaps=)`)·상인방·문 JSON·충돌 대상·조명·지형 패드가 모두 일관되게 따라온다. 기존 검사(`door_report`·`door_sweep`·`visibility`)도 그대로 쓴다 |

### 3.2 공통 준비(`maplib.py`, `assets.py`)

1. `HALF`를 설정값으로: `HALF = globals().get('PLAY_HALF', 52.5)`. `build_all.py`가 `PLAY_HALF`를 넘길 수 있게 한다(나중에 크기를 다시 조정할 때 한 값만 바꾸도록).
2. §1.2 표의 하드코딩 값을 `HALF` 식으로 교체.
3. 도우미 추가:

```python

def gap_report(m, z_max=2.5):
    ...
```

`gap_report`는 `door_sweep.py`처럼 `build_all.py`의 옵션(`GAPS=True`)으로 돌려 보고만 한다. **최종 판정은 실제 충돌체로 하는 Unity 검사다.**

4. `scatter()`에 “물체 지름” 인자를 받아 간격을 `max(spacing, 지름 + MIN_GAP)`로 강제하는 옵션을 더한다(R9). 지름은 `get_asset(name)`의 바운딩 × 배율.
5. `dress_paths`는 각 맵에서 `cluster=(1, 1)`, `spacing` 확대로 호출한다(R9).

### 3.3 줄이는 순서(맵마다)

1. **랜드마크와 고정 크기 시설**을 먼저 놓는다(크기 불변, 필요한 통로 7 m를 포함한 자리를 `m.blockers`로 예약).
2. **건물(절차 생성 벽)**의 치수를 내용물 + 통로 기준으로 다시 정한다. 문은 `wall(gaps=[(거리, 7 이상)], gap_h=7 이상)`.
3. 도로·광장·고리길을 새 반경으로 그린다(폭 6~8 m — 괴물 팔 폭이 지나가는 주 통로).
4. 지형 특징을 비율로(좌표·R·H 모두 × 0.3, 경사 불변).
5. 산포·장식은 R9의 개수·간격으로.
6. 경계 가까운 것은 R5로 붙이거나 뗀다.
7. 조명(`light_setup.EXTRA`, 스크립트의 `m.light`), `refs`, `gamecam`, `visibility.LM` 좌표를 옮긴다.

## 4. Unity 변경(`Assets/Editor/Maps/MapSceneBuilder.cs` 외)

**① 맵 반폭을 경계 벽에서 계산** — `MapHalfExtent`(172) 대신. `AddMissingColliders`(플레이 영역 밖 생략), `ReportMissingColliders`, `CountHoles`, `FindSpawn`,
반사 프로브·낙하 영역 크기가 이 값을 쓴다. 경계가 없으면 예전 값으로.

```csharp
private const float LegacyMapHalfExtent = 172f;

// 투명 경계 벽(*_COL_Boundary) 네 개의 안쪽 면 = 플레이 영역 반폭(스크립트의 HALF - 0.5).
private static float PlayHalfExtent(Transform mapRoot)
{
    float half = float.MaxValue;
    foreach (MeshFilter mf in mapRoot.GetComponentsInChildren<MeshFilter>(true))
    {
        if (!mf.name.Contains("COL_Boundary")) continue;
        Bounds b = mf.GetComponent<Renderer>().bounds;
        half = Mathf.Min(half, Mathf.Max(Mathf.Abs(b.center.x) - b.extents.x, Mathf.Abs(b.center.z) - b.extents.z));
    }
    return half < float.MaxValue ? half : LegacyMapHalfExtent;
}
```

## 6. 검사 — “못 지나가는 곳 없음”의 판정

두 단계로 검사하고, **둘 다 통과해야 맵 완료**다.

### 6.1 Blender 단계(빠른 반복, 기존 도구 + 1개)

| 검사 | 도구 | 통과 기준 |
|---|---|---|
| 문 치수 | `Map.door_report()`(`maplib.py:715`) | `too_small` 없음(폭·높이 7 m 이상) |
| 문 통과 | `door_sweep.py`(`build_all.py`의 `SWEEP=True`) — 문 법선을 따라 안팎 7 m, 옆 오프셋 −2.5/0/+2.5 m, 높이 0.8/2.7/5.0 m 광선 | `blocked` 없음 |
| 경사 | `Map.terrain_report()` | 걷는 면 최대 20°, 길 위 최대 경사 보고 |
| 랜드마크 가시성 | `visibility.py`(`VISIBILITY=True`) | 기본 시점 표본 비율이 현재와 비슷하거나 높음(작아진 맵이라 대부분 오른다) |
| 틈(신규) | `gap_report`(`GAPS=True`) | 금지 틈 0(사전 점검) |

### 6.2 Unity 단계(최종 판정, `MapPassabilityCheck` — 빌드된 씬의 실제 충돌체)

이전 판 조사에서 NewMap에 대해 수동으로 돌린 검사(격리 프리뷰 씬 + 격자 + 캡슐 겹침 검사 + 연결 영역)를 도구로 만든 것이다. 크기는 코드에 적지 않고 **프리팹에서 읽는다**
(`HideOrSeekPlayer` 캡슐, `MonsterPlayer` 캡슐·렌더러 경계·`MonsterGrabKillTrigger` 구의 중심과 반지름).

- 격자: 0.5 m, 경계 안쪽 전체. 각 칸에서 아래로 광선을 여러 번 쏴 **모든 층의 바닥**(실내 바닥·다리·받침 위)을 찾는다. 설 수 있는 면 = 법선 기울기 45° 이하, 경계 벽·트리거 제외.
- 칸마다: 쿠키 캡슐이 들어가는지, 괴물 캡슐이 들어가는지, 괴물 몸 통로(반지름 1.85 m, 높이 2~5.3 m)가 비었는지.

| # | 검사 | 방법 | 실패 조건 |
|---|---|---|---|
| ① | 문·실내 통로(R3) | 문(`InteractableDoor`)·상인방마다 개구부 폭·높이 측정 + 괴물 몸 통로를 문 법선 ±7 m로 쓸기(문짝 열린 상태) | 폭·높이 < 7 m, 쓸기 중 충돌 |

| ③ | 애매한 틈(R4·R5) | 걷는 높이 장애물 지도에서 빈 칸마다 가장 가까운 장애물까지 거리(거리 변환) → 통로 중심선(능선 칸)의 폭 = 2 × 거리 | 중심선 폭이 0.6 m 초과 4.0 m 미만인 구간(경계 벽도 장애물로 포함) |

| ⑤ | 스폰(R10) | `PlayerSpawnPos`·`MonsterSpawnPos` 주변 흩뿌림 반경(`GameSettings`)의 모든 칸 | 주 영역 밖 칸이 있음 |
| ⑥ | 충돌체 누락 | 빌더의 `ReportMissingColliders` 결과를 가져옴 | 1개 이상 |

- 결과: `Assets/Maps/<맵>/<맵>_Passability.json`(항목별 수·좌표·둘러싼 물체 이름·씬 해시) + **검토용 지도 PNG**(0.5 m = 1 px, 색: 주 영역·막힌 칸·금지 틈·쿠키 전용·스폰).
  빌드 보고에 한 줄 요약. PNG는 `Resources` 밖에 두어 빌드에 들어가지 않게 한다.
