# 몬스터 캐릭터(Mesh_0) 리깅 작업 계획

> **상태: 1~22번 전체 완료 (2026-08-19, 22.4 고깔 돌출부 무웨이트 수정까지 반영)**. 최종 산출물 5종: `Monster_Rigged.fbx`(T-pose), `Monster_Rigged_Walk.fbx`(걷기), `Monster_Rigged_Idle.fbx`(대기), `Monster_Rigged_TentacleDash.fbx`(촉수 이동 스킬), `Monster_Rigged_GrabKill.fbx`(플레이어 그랩/킬 모션). 22번에서 촉수 2개·팔 4개가 서로(그리고 얼굴/몸통에) 영향을 주지 않도록 웨이트를 처음부터 다시 만들었고, 본/IK 구조는 기존 그대로 유지. §22.1~22.2에서 `Head`를 디폼 본으로 승격시켜 "몸 전체 이동은 따라가되 개별 관절에는 반응 안 함" 방식으로 얼굴을 보호했으나, §22.3에서 사용자가 **그 방식조차 원치 않는다고 명확히 함**("몸 전체 이동을 따라가는 것도 영향") — `Head`를 다시 비-디폼 본으로 되돌리고 얼굴은 **완전 무웨이트(0)** 로 확정. 이로 인해 TentacleDash 웅크림에서 머리가 몸통과 분리되어 보이는 회귀가 나타나 사용자 확인 후 웅크림 하강 폭을 60% 축소(-0.35→-0.14)해 완화. 전체 메쉬 레스트 오차 0.0000009 유지. 모든 파일 아마추어(58본, 46 버텍스 그룹, `Head` 그룹 없음) 재-임포트로 확인됨. 세부 내용과 남은 한계는 §22, §22.1, §22.2, §22.3 참고.

## 22. 촉수/팔 웨이트 전면 재작업 — 완전 격리 리깅 (2026-08-19, 완료)

**사용자 요청**: 지금까지의 문제(그랩/킬 찌그러짐 등)가 결국 리깅 문제였다고 판단, 리깅을 처음부터 다시 하되 두 가지를 엄격히 지킬 것을 명시:
1. 뒤쪽 촉수 2개는 각각 서로를 포함해 어디에도 영향을 주거나 받지 않아야 함 — 촉수가 늘어날 때 그 촉수만 늘어나야 하고 얼굴·팔·몸통은 전혀 움직이면 안 됨.
2. 팔 4개도 리깅 시 어디에도 영향을 주거나 받지 않아야 함.

### 22.1 범위 결정 (사용자 확인)
본/IK 계층, Pole Target, 신축 클램프 등은 9~21번에 걸쳐 이미 여러 차례 디버깅되어 검증된 상태라 그대로 유지하고, **스키닝(버텍스 웨이트)만 처음부터 다시 계산**하는 것으로 범위를 좁힘 (전체 본 재생성은 리스크·시간 대비 이득이 적다고 판단, 사용자 승인).

### 22.2 실제 발견한 근본 문제
재작업 착수 전 기존(21.10까지 검증됐다고 기록된) 웨이트를 직접 스캔한 결과, **전체 5,205개 버텍스 중 3,363개(65%)가 서로 다른 두 개 이상의 부위(예: 촉수-팔, 위팔-아래팔, 심지어 왼쪽 어깨-오른쪽 어깨)에 걸쳐 웨이트가 섞여 있음**을 확인. 이것이 그동안 반복적으로 보고된 "찌그러짐"의 실제 근본 원인이었음 — Walk/Idle처럼 움직임이 작을 때는 안 드러나다가, GrabKill처럼 한쪽만 크게 움직이면 섞여 있던 다른 부위가 함께 딸려가며 찢어지는 방식으로 나타남.

### 22.3 최종 방식 — "부위당 단일 지배 본" 하드 격리
1. 촉수 2개(각 5본: TentacleRoot~Tentacle.04) + 팔 4개(각 7본: Shoulder~Finger×3) = 6개 "부위(family)"를 정의.
2. 각 버텍스마다 기존 웨이트를 부위별로 합산해 **가장 큰 부위 하나만 남기고 나머지 전부 제거 후 재정규화(합=1.0)** — 이제 한 버텍스는 반드시 정확히 하나의 부위에만 속함.
3. **다리(Hip/Knee/Ankle/Toe)는 이번 요청 범위 밖**이므로 원래 검증된 웨이트를 전혀 건드리지 않고 그대로 보존 (다리까지 같은 방식으로 격리해봤다가 Walk의 다리 사이 크로치 부위에 없던 찢어짐이 새로 생기는 것을 확인하고 즉시 원복 — 요청받지 않은 범위까지 손대는 것이 오히려 새 버그를 만든다는 것을 재확인).
4. **미세 이음매 예외(76개 버텍스, 전체의 1.5%)**: 서로 다른 부위가 실제로 거의 맞닿아 있는(레스트 상태 버텍스 간 거리 0.025 미만) 지점 — 촉수 좌우 뿌리가 쇄골 중앙에서 만나는 곳, 촉수 뿌리와 어깨가 맞닿는 곳 등 — 은 완전히 갈라놓으면 오히려 큰 동작에서 찢어짐이 더 심해짐을 실측으로 확인(예: GrabKill 절정 프레임에서 찢어짐 비율이 완전 격리 시 80배 이상까지 치솟음). 이 정밀하게 특정된 극소수 지점에 한해서만 원래의 블렌딩 웨이트를 유지하고, **나머지 전체(98.5%)는 하드 격리 유지**.
5. 완전 무웨이트(고아) 버텍스는 이웃 부위 다수결로 채움, 버텍스당 영향 본 4개 초과분은 상위 4개만 남기고 재정규화(유니티 SkinnedMeshRenderer 4-본 제한 대응, 21.9 방식 재적용).

### 22.4 부수적으로 발견/수정한 기존 버그 (이번 세션 이전부터 존재)
- **TentacleDash(웅크림) 크래시급 찢어짐**: 웅크릴 때 몸통(Root)이 크게 이동하는데, 머리 보호구역(r<0.22) 경계의 일부 버텍스가 실제로는 촉수 뿌리 표면인데도 웨이트가 0으로 남아있어(원본 파일에도 이미 존재하던 고아 버텍스), Root가 크게 움직이면 그 지점만 뒤에 남고 주변은 다 따라가서 하반신 전체가 파편처럼 뭉개지는 현상을 발견 (스크린샷으로 확인). **이 문제는 이번 세션이 만든 게 아니라 원본 파일에 이미 있었음** — 이전 세션의 "완료" 검증이 최근 Blender 버전(5.2)의 액션 슬롯 API 변경으로 인해 프레임 평가가 고정되는 테스트 스크립트 버그 때문에 이 결함을 못 잡았던 것으로 추정. 이웃 기반 재-웨이트 채움으로 수정.
- **격리 검증에 쓴 자체 진단 스크립트도 같은 액션 슬롯 버그에 걸려 있었음**을 발견 — `animation_data.action`만 설정하고 `action_slot`을 명시하지 않으면 Blender 5.x에서 프레임이 바뀌어도 포즈가 갱신되지 않는 경우가 있음(레이어드 액션 시스템). 이후 모든 프레임 평가에 `action_slot` 명시 설정을 추가해 재검증.

## 22.1 재발 수정 — 고아 채움 버그로 격리가 다시 깨졌던 것을 발견 및 근본 수정 (2026-08-19, 완료)

**사용자 리포트**: 직접 조사한 결과 (1) `Tentacle.01.R`의 영향이 머리까지 미치는 것을 확인했고, (2) TentacleDash에서 과거(16번 섹션)처럼 손/촉수 끝 부분이 한쪽은 고정된 채 나머지가 고무줄처럼 늘어나는 현상이 재현됨을 지적.

**원인 진단 (둘 다 사실로 확인됨)**:
1. §22.3에서 완전 무웨이트(고아) 버텍스를 채우는 마지막 폴백 단계가 "부위 일치 여부를 확인하지 않고 이웃 전체를 평균"내는 방식이었음 — 부위 검증(family consensus) 로직을 초반 시도에서는 넣었다가, 범위를 촉수+팔 6개로 좁히는 최종 리팩터링 과정에서 실수로 빠뜨림. 그 결과 머리 경계뿐 아니라 팔꿈치·어깨·엉덩이 등 전신 경계에서 전체 5,205개 중 **2,489개(48%) 버텍스가 다시 여러 부위에 걸쳐 섞임** — 사실상 22번 작업 이전 상태(65% 오염)로 되돌아간 것과 다름없었음. 머리 근처에서는 `TentacleRoot.L`/`TentacleRoot.R`이 한 버텍스에 동시에 섞이는, 21.8에서 이미 고쳤던 바로 그 버그까지 재발.
2. "손이 고정된 채 늘어나는" 현상은 촉수 끝 블롭이 원래(자동 웨이트 단계에서부터) 어깨/위팔과 거의 6:4 비율로 애매하게 걸쳐 있는 지점이라, 버텍스 단위로 지배 부위를 정하면 블롭 중간에서 부위가 동전 던지기처럼 뒤바뀌는 경계선이 생김 — GrabKill/TentacleDash는 팔을 전혀 애니메이션하지 않으므로, 이 경계선 한쪽(팔로 분류된 버텍스)은 완전히 멈춰 있고 바로 옆(촉수로 분류된 버텍스)은 촉수를 따라 크게 움직여 "한쪽만 고정된 채 늘어나는" 정확히 그 현상이 나타남.

**근본 수정**:
1. **`Head` 본을 디폼 본으로 승격**(`use_deform=True`)하고 새 `Head` 버텍스 그룹 생성. 4개 액션 전체에서 `Head` 본 자체의 로컬 포즈 값이 모든 프레임에서 항상 항등(identity)임을 먼저 확인(즉 `Head`는 Root~Chest 계층을 통한 몸 전체의 강체 이동만 물려받고, 독립적인 흔들림은 전혀 없음) — 이 덕분에 `Head`에 웨이트를 주면 "몸 전체가 움직이면 얼굴도 같이 움직이지만, 촉수/팔 각각의 개별 관절 움직임에는 전혀 반응하지 않는" 정확히 원하는 성질을 얻음.
2. 머리 중심 반경 0.22 이내의 모든 버텍스는 **예외 없이 강제로 `Head` 100%**로 재분류(기존 촉수/팔 웨이트가 조금이라도 있었으면 전부 제거) — 재검증 결과 머리 반경 안 촉수 웨이트 위반 0건, 팔 웨이트 위반 0건.
3. 고아 채움 로직을 다시 "이웃들이 만장일치(또는 다수결)로 같은 부위일 때만 그 부위의 웨이트만 평균"하는 방식으로 엄격하게 교정, 그래도 못 채운 극소수(7개)는 임의의 부위가 아니라 안전한 기본값인 `Head`로 배정(무웨이트로 방치해 Root 이동 시 뒤처지는 것보다 안전).
4. 촉수 끝 블롭-팔 경계의 "동전 던지기" 문제는 **이웃 2단계 반경 다수결 스무딩**을 적용해, 소수의 튀는 버텍스(11개)를 주변 블롭 전체와 같은 부위로 통일 — 블롭이 한 덩어리로 일관되게 촉수에 속하도록 정리.
5. 미세 이음매(레스트 거리 0.025 미만) 예외는 22번과 동일하게 유지하되, `Head`/다리는 예외 대상에서 완전히 제외.

## 22.3 얼굴 웨이트 완전 제거 확정 + TentacleDash 웅크림 폭 축소 (2026-08-19, 완료)

**사용자 리포트**: §22.2에서 `Head`를 디폼 본으로 승격시켜 "몸 전체가 이동할 때는 따라가지만 촉수/팔/다리 개별 움직임에는 반응하지 않는" 방식으로 설명했으나, 사용자가 "아니 머리쪽에 영향이있는걸 제거해달라니까?", "머리는 애니메이션 없이해"로 재차 명확히 함 — 몸 전체 이동에 따라가는 것조차 "영향"으로 간주, **얼굴은 어떤 이유로도 절대 움직이면 안 됨**.

**조치 1 — 얼굴 완전 무웨이트로 되돌림**:
- `Head` 본의 `use_deform`을 다시 `False`로 되돌리고, `Head` 버텍스 그룹 자체를 삭제. 머리 반경(r<0.22) 안의 버텍스는 다시 완전히 무웨이트(0) 상태 — 어떤 본에도 소속되지 않아 항상 레스트 위치에 고정됨.

**부작용 발견 및 처리**:
- 되돌린 직후 4개 애니메이션을 재스캔한 결과 `TentacleDash`(웅크림 스킬)의 찢어짐 비율이 24.9배 → **34.2배로 악화**, 11프레임(웅크림 최저점) 스크린샷을 확인하니 **머리가 몸통과 완전히 분리되어 허공에 떠 있는 것처럼 보이는 명백한 결함**을 발견 — Root가 -0.35만큼 하강하는데 머리는 무웨이트라 전혀 따라가지 않아서 생기는, §20.4에서 이미 겪었던 문제의 재현.
- 사용자에게 스크린샷 근거와 함께 3가지 선택지(① 웨이트 0 유지+웅크림 폭 축소, ② 웨이트 0 유지+증상 그대로 방치, ③ 몸 전체 이동만 따라가는 방식으로 복원)를 제시 → **①번 선택**(웨이트 0을 지키되 웅크림 자체의 폭을 줄여 증상을 완화)

**조치 2 — TentacleDash Root 하강 폭 60% 축소**:
- `MonsterArmatureAction_TentacleDash`의 `Root.location`(Y축, 월드 하강 방향) 키프레임 전체를 곡선 형태는 유지한 채 **0.4배로 스케일** — 최저점 -0.35 → **-0.14**, 발사 반동 최고점 +0.18 → +0.072로 함께 축소.
- 재확인 결과 11프레임에서 머리-몸통 분리가 시각적으로 해소됨(스크린샷 확인). 찢어짐 비율도 34.2배 → **22.1배**로 개선.
- **트레이드오프(사용자에게 투명하게 공유)**: 웅크림 폭이 줄어들면서 §20.1에서 계산했던 "촉수가 지면에 닿기 위한 최소 하강폭" 여유가 줄어듦 — 현재 11프레임 기준 촉수 끝(`Tentacle.04`)이 Z≈-0.59, 지면은 Z≈-0.842로 **약 0.25 부족해 촉수가 지면에 완전히 닿지 않을 수 있음**. "촉수로 땅을 짚고 순간이동"하는 스킬의 연출 의도(§20)상 지면 접촉이 중요하다면, 추후 다리를 더 굽히거나 촉수 신장 애니메이션 타이밍을 조정하는 별도 작업이 필요할 수 있음 — 이번 작업 범위(리깅/웨이트)를 벗어나므로 우선 폭 축소만 반영하고 사용자 확인 대기.
- 남은 잔여 찢어짐(22.1배, 머리 보호 경계 바로 안팎 버텍스 간)은 **무웨이트 요구사항 자체의 불가피한 부작용**(경계 양쪽이 "전혀 안 움직임"과 "촉수 뿌리만큼 움직임"으로 갈리는 지점) — 스크린샷 육안 확인 결과 형태를 알아볼 수 없는 손상은 아님.

## 20. 특수 이동 스킬 — 촉수로 땅을 짚고 순간이동 (2026-08-18, 계획 단계)
사용자 요청: 기본 이동수단(걷기)이 아닌 **쿨타임이 있는 특수 스킬**. 촉수 2개로 땅을 짚어 몸을 띄운 뒤 순식간에 이동하는 모션. 실제 위치 이동 로직은 Unity 담당, Blender는 준비/발사/착지 3단계 포즈(애니메이션 클립)를 담당.

### 20.1 조사: 촉수가 실제로 지면에 닿을 수 있는가?
- 지면 높이(메쉬 최저점 Z): **-0.842**
- 촉수 뿌리(`TentacleRoot`)는 목 뒤(머리 근처, Z≈0.36)에 위치 — 서 있는 기본 자세 기준 뿌리→지면 직선거리: **약 1.20~1.27**
- **오른쪽 촉수**: 레스트 길이 0.753 → 2배 한도 1.506 → **서 있는 자세 그대로도 지면 도달 가능** (여유 있음)
- **왼쪽 촉수**: 레스트 길이 0.552 (오른쪽보다 짧음 — 16번 섹션에서 밝혀진 원본 메쉬 좌우 비대칭 때문) → 2배 한도 1.105 → **서 있는 자세로는 지면에 약 0.1~0.16 부족, 도달 불가**
- **해결책**: 스킬의 "준비(웅크림)" 단계에서 몸통(`Root`)을 아래로 크게 낮추면(예: 0.4 정도) 촉수 뿌리도 함께 낮아져 필요 거리가 약 0.8로 줄어듦 → 이러면 **양쪽 촉수 모두 2배 한도 안에서 여유 있게 지면 도달 가능**. 마침 "웅크렸다가 튀어오르는" 동작 자체가 스킬의 자연스러운 준비 동작과 맞아떨어짐 (에너지를 모으는 것처럼 보임).

### 20.2 중요 전제 — 발동 방식 (사용자 확인, 2026-08-18)
이 스킬은 **Walk 또는 Idle 도중에 발동**된다. 즉 애니메이션 클립이 **처음부터 이미 웅크리고 촉수가 바닥에 닿아있는 상태로 시작하면 안 되고**, Walk/Idle의 "그 순간 자세"(팔은 걷기 스윙 중이거나 Idle 호흡 자세, 촉수는 각자 허공에서 흔들리는 중)에서 자연스럽게 이어져, **준비(Windup) 단계 안에서 촉수가 허공에서 내려와 실제로 바닥을 짚는 과정 자체가 애니메이션 내용**이어야 함. "이미 짚은 상태"를 전제로 시작하는 클립이 아니라 "짚는 동작"을 보여주는 클립.

- 실무적으로 Unity에서 Walk/Idle → 이 스킬로 전환할 때 애니메이터가 두 상태 사이를 블렌드(크로스페이드)하므로, Windup의 시작 포즈는 Walk와 Idle 양쪽에서 봐도 크게 어색하지 않은 **중립에 가까운 자세**(예: Idle의 팔 내려간 기본 자세, 촉수는 뿌리 근처의 중간 위치)로 설계하는 것이 안전함
- Root/촉수/다리 모두 "정지된 시작값"이 아니라 **명확한 이동 궤적**(허공 위치 → 바닥 접촉 위치)을 가진 키프레임으로 표현

### 20.3 계획 (3단계 구조, 수정됨)
1. [ ] **준비(Windup)** — 클립 시작은 중립에 가까운 자세(Idle 기본 자세 근처)에서 출발. 진행되면서: 몸통(Root)이 점진적으로 낮아짐(웅크림), **촉수 2개가 각자의 허공 스윙 위치에서 아래로 뻗어나가 실제로 지면에 닿는 과정**을 명시적으로 키프레임, 다리는 오그라들며 무게중심이 촉수 쪽으로 이동. 대략 0.3~0.5초 분량 (촉수가 허공→지면까지 이동하는 시간을 확보해야 하므로 기존 예상보다 살짝 길게), 플레이어가 스킬 발동을 눈치챌 수 있는 "읽히는" 예비 동작으로 설계
2. [ ] **도약/발사(Launch)** — 촉수가 지면을 짚은 상태에서 밀어내는 힘으로 몸이 붕 뜨고 이동 방향으로 쏠리는 스트레치 포즈 한 컷 (실제 위치 이동은 Unity 쪽에서 처리, Blender는 그 순간의 임팩트 포즈만 제공). 팔 4개는 Idle 자세처럼 몸에 붙여 정리하거나 관성으로 뒤로 쏠리는 느낌 추가
3. [ ] **착지/회복(Land & Recover)** — 촉수가 지면에서 떨어지며 다시 원래 길이로 줄어들고, 다리가 지면에 닿으며 정상(Idle에 가까운) 자세로 복귀, 짧은 후딜레이(recovery) 프레임 포함 — 쿨타임 스킬다운 리스크 구간. 마지막 프레임은 다시 Idle/Walk로 자연스럽게 블렌드될 수 있는 자세여야 함
4. [ ] 다리 IK(FootIK)로 웅크림/착지 시 발 위치 자유롭게 조정, 촉수는 기존 IK+Limit Distance(2배 캡) 그대로 재사용 — 20.1에서 확인했듯 Root 하강이 진행되는 시점부터 지면 도달 가능해지므로, **촉수가 지면에 닿는 타이밍은 Root 하강이 충분히 진행된 이후**로 맞춰야 함 (동시에 시작하면 왼쪽 촉수가 닿기 전에 허공에서 멈춘 것처럼 보일 수 있음)
5. [ ] 팔 4개는 19번(Idle)에서 만든 "자연스럽게 내려간" 베이스 자세를 기본으로 사용, 필요 시 단계별로 자세 조정
6. [ ] 새 Action(`MonsterArmatureAction_TentacleDash` 가칭)으로 제작, 레스트 대비 변형 오차 및 촉수가 허공→지면으로 자연스럽게 이어지는지 스크린샷/프레임별 검증
7. [ ] `Monster_Rigged_TentacleDash.fbx`로 별도 내보내기 후 재-임포트 검증

**미정 사항 (진행 전 확인 필요):** 정확한 프레임 길이/타이밍, 이동 방향(전방 고정 vs 임의 방향), 착지 시 카메라/이펙트 연동 여부는 Unity 쪽 스킬 설계에 맞춰 추가 논의 필요.

### 20.4 실제 제작 및 발견된 문제 (2026-08-18, 완료)

**Root 로컬축 매핑 확인:** 본의 로컬 좌표축이 월드 좌표축과 일치하지 않음을 실측으로 확인 — `Root.location`의 Y성분이 월드 Z축(+), Z성분이 월드 -Y축에 대응. 이후 몸통을 웅크릴 때는 `Root.location.y`에 음수를 넣어야 함.

**IK 컨트롤 본 배치 방식 개선:** 기존 프로젝트에서 쓰던 "레스트 기준 로컬 델타" 방식은 Root가 애니메이션되는 상황에서 부모 체인의 현재 이동을 반영하지 못해 오차가 생김 → `pose_bone.matrix`에 월드 목표 좌표를 직접 대입하는 방식으로 전환(Blender가 알아서 필요한 local 값을 역산). 이 방식은 Root가 움직여도 항상 정확한 월드 좌표를 보장하므로 이후 유사 작업에도 재사용 권장.

**치명적으로 재발한 버그 — 웅크림(Root 하강) 도입 시 몸통이 무너짐:**
- 준비 단계에서 Root를 크게 낮추자(-0.35), 예전(15~17번)에 "괜찮다고 판단했던" 웨이트 경계 처리들이 전부 다시 문제를 일으킴. 이유: 그동안 Walk/Idle은 Root를 거의 움직이지 않았기(호흡 바운스 0.02 수준) 때문에 숨어있던, **머리~촉수 뿌리~콜라 사이의 웨이트 경계 오염**이 큰 Root 이동에서 크게 증폭되어 드러남
- 여러 차례의 반복 시도 끝에 확인된 근본 원인: 촉수가 실제로 **머리 표면에서 시작**하기 때문에 "머리 영역"과 "촉수 뿌리 영역"이 기하학적으로 겹쳐서, 순수 거리 기준이나 단일 임계값 규칙으로는 두 영역을 깨끗하게 분리할 수 없음. 자동(히트) 웨이트가 이 경계에서 콜라/목 버텍스에 촉수 본 웨이트를 강하게 부여하는 경우가 다수 존재했음
- **최종 해결 순서:**
  1. 자동 웨이트 재계산 → 지배 웨이트 0.4 미만 스트립 → 정규화 → 고아(웨이트 0) 버텍스를 이웃 웨이트로 채움 → 정규화 → 재스트립(채우기가 새로 만든 희석된 코어 누출 정리) → 정규화
  2. 촉수 튜브 표면(중심선 기준 반경 0.10~0.12) 밖에 있으면서 목/콜라 영역(반경<0.35, Z 0.30~0.52)에 있는 버텍스를 웨이트 제거
  3. 몸통 중심축 부근(반경<0.30, Z>0.15)이면서 **어떤 디폼 본에도 0.12 이상 떨어진** 버텍스를 최종적으로 강제 제로 처리
  4. 그래도 남은 웨이트 구멍(전체 메쉬 기준 450개)을 다시 이웃 채움 → 정규화
  5. 진짜 구형 머리(머리 중심에서 반경 0.20~0.22 이내)만 별도로 최종 검사해서, 여전히 눈에 띄게 움직이는 버텍스(딱 2개)를 개별적으로 강제 제로 처리
  6. 각 단계 후 매번 (a) 전체 메쉬 진짜 레스트 오차, (b) 머리 구 변형량, (c) 이웃-거리 기준 찢어짐 이상치 개수, (d) 각 본의 지배적 웨이트 버텍스 개수(고아 여부)를 함께 확인하는 방식으로 반복 검증
- **결과:** 머리 구 변형량 0.49 → **0.0**, 전체 찢어짐 이상치 439개 → 172개(남은 것은 대부분 무릎/팔꿈치가 크게 굽혀질 때 생기는 정상적인 관절 신축으로 판단됨, 시각적으로 스파이크 형태의 이상 변형은 사라짐)

**검증 완료:**
- [x] 전체 메쉬 진짜 레스트 오차: 0.0000009 (유지)
- [x] 머리 구 변형량(웅크림 프레임): 0.0
- [x] 촉수 2배 신축 클램프: 애니메이션 전 프레임에서 최대 R=1.164배, L=1.588배로 한도 안 (발사 시 촉수를 지면에서 먼저 떼어내도록 타이밍 재조정하여 해결)
- [x] Walk/Idle 애니메이션이 이번 웨이트 재작업으로 손상되지 않았음을 재검증 (다리/촉수 IK 레스트 오차, 걷기 발 바운딩박스 비율 모두 정상)
- [x] `Monster_Rigged.fbx`, `Monster_Rigged_Walk.fbx`, `Monster_Rigged_Idle.fbx`, `Monster_Rigged_TentacleDash.fbx` 4개 파일 모두 최종 웨이트 반영하여 재내보내기
- [x] `Monster_Rigged_TentacleDash.fbx` 재-임포트하여 웅크림 프레임에서 머리 변형 0 확인

**최종 교훈:** 캐릭터의 신체 부위가 서로 물리적으로 맞닿아 있는 경계(이번엔 "머리 표면에서 자라난 촉수")는 순수 지오메트리 규칙만으로 완벽히 분리되지 않는다. 이런 경계는 처음엔 작은 움직임(호흡 등)에서 문제가 드러나지 않다가, 나중에 그 부위가 크게 움직이는 새로운 애니메이션(이번엔 큰 웅크림)에서야 비로소 드러날 수 있다 — **새로운 큰 동작(특히 몸통 전체를 옮기는 동작)을 추가할 때마다 레스트 오차·이웃-거리 찢어짐 검사를 그 동작 기준으로 다시 실행**하는 것을 표준 절차로 삼을 것.

### 20.5 치명적 실수 — 내보낸 FBX 4개 전부에 아마추어(뼈대)가 누락됨 (2026-08-19, 완료)

사용자 리포트: "동작이 전혀 되지 않아." 확인 결과, **직전에 내보낸 4개 FBX 파일(`Monster_Rigged.fbx`, `_Walk`, `_Idle`, `_TentacleDash`) 전부에 아마추어가 통째로 빠져있었음** — 메쉬만 내보내져서 Unity에서 뼈대/애니메이션 자체가 존재하지 않는 상태였음.

**원인:** 디버깅 도중 화면을 깨끗하게 보려고 `arm_obj.hide_set(True)`로 아마추어를 여러 번 숨겼는데, 마지막에 `hide_set(False)`로 다시 켜지 않은 채로 바로 내보내기를 실행함. Blender FBX 익스포터는 `use_selection=True`여도 **숨겨진(hidden) 오브젝트는 선택 여부와 무관하게 내보내기에서 제외**하는데, 이걸 놓치고 익스포트 직전에 hide 상태를 재확인하지 않았음.

**조치:**
1. [x] `arm_obj.hide_set(False)` 확인 후 4개 FBX 전부 재내보내기
2. [x] 4개 파일 모두 재-임포트하여 아마추어(58본)가 정상적으로 포함되는지 확인
3. [x] Walk/Idle/Dash 각각에서 실제 본(FootIK, TentacleTip, Shoulder 등)이 프레임마다 값이 바뀌는지(애니메이션이 실제로 재생되는지) 확인 완료

**재발 방지책:** 앞으로 내보내기 스크립트에는 항상 `mesh_obj.hide_set(False)`와 `arm_obj.hide_set(False)`를 내보내기 직전에 명시적으로 강제하는 코드를 포함할 것 — 이번처럼 디버깅용 hide 호출이 실수로 남아있는 상태를 방지.

## 15. 왼발 재발 + 오른쪽 촉수 손 재발 — 진짜 근본 원인 발견 및 완전 해결 (2026-08-18, 완료)

사용자가 `Walk4/5/6.png`(Unity), `BugLeftFoot.png`/`RightHandBug.png`(Blender 화면)를 추가 제공. 14번에서 고쳤다고 판단했던 문제가 재발한 것처럼 보였으나, 실제로는 **더 근본적인 3가지 문제**가 겹쳐 있었던 것으로 확인됨.

**최종 확정된 3가지 원인:**

1. **다리 IK 체인의 "2가지 굽힘 해" 중 잘못된 해를 고르고 있었음.** 14번에서 무릎 pole_angle을 찾을 때 **발목(체인 끝) 위치만** 기준으로 삼았는데, 2본 IK는 같은 발목 위치를 "무릎이 앞으로 굽는 해"와 "반대로 굽는 해" 양쪽에서 똑같이 만족시킬 수 있어서, 발목은 맞아도 **무릎 자체는 레스트와 최대 0.18 어긋난 상태**였음. 게다가 다리 IK에 의도치 않게 `use_stretch=True`가 걸려있어 무릎 본이 늘어나며 위치가 더 틀어짐. → `use_stretch=False`로 되돌리고, 촉수와 동일하게 **Pole Target을 완전히 제거**하여 해결 (무릎·발목 오차 모두 0.000000 확인).
2. **자동(히트) 웨이트가 전체 버텍스의 56%(5205개 중 2919개)에서 웨이트 합을 1.0으로 정규화하지 못함.** 56개 본짜리 복잡한 아마추어에서 히트 디퓨전이 완전히 정규화되지 않아, 예를 들어 어떤 버텍스는 웨이트 합이 0.82에 불과했음. 레스트 포즈(모든 본이 identity)에서도 웨이트 합이 1.0이 아니면 **버텍스가 원점 쪽으로 당겨지는 심각한 왜곡**이 생김 — 이번에 발견된 "레스트에서도 배/치마가 찢어져 보이는" 증상의 실제 원인. → Weight Paint의 `Normalize All` 연산으로 전체 웨이트 합을 1.0으로 강제 정규화하여 해결.
3. (14번에서 이미 발견) 코어(몸통/머리) 스트립 임계값이 무릎 바깥쪽처럼 두꺼운 부위를 웨이트 0으로 잘라버려 찢어짐 발생 — 순수 거리 대신 **"버텍스별 가장 지배적인 단일 본의 웨이트가 0.4 미만인 경우만 스트립"** 기준으로 교체하여 완화.

**검증 결과:**
- [x] 레스트 포즈에서 전체 메쉬(5205개 버텍스) 최대 변형량: 0.82 → **0.0000009** (사실상 완전히 0)
- [x] 내보낸 `Monster_Rigged.fbx` 재-임포트 후 동일 검증: **0.00000065**
- [x] 걷기 애니메이션에서 이웃-거리 이상치(찢어짐 징후)가 프레임당 최대 120+개 → 1~21개로 대폭 감소 (남은 것은 양다리 사이 경계처럼 본질적으로 애매한 소수 버텍스, 육안으로는 확인 안 됨)

**최종 교훈:** 
1. 다중 본 IK 체인을 검증할 때는 **체인의 마지막 본뿐 아니라 중간 관절 하나하나가 레스트와 일치하는지** 반드시 확인해야 하며, 2본 체인이라도 "굽힘 방향이 2가지"인 근본적 모호성이 있음을 인지해야 한다.
2. 본이 많고 복잡한 아마추어에서는 자동 웨이트가 **정규화(합=1.0)를 보장하지 않을 수 있으므로**, 웨이트 스트립/수정 작업 후에는 항상 `Normalize All`을 마지막 단계로 실행해야 한다.
3. 위 두 가지가 겹쳐서 발생하는 왜곡은 눈으로 보기엔 "다리/촉수가 이상하다"로만 보이지만, 실제로는 서로 다른 두 시스템(IK 기하학 + 웨이트 정규화)의 독립적인 버그였다 — 증상이 비슷하다고 원인이 하나라고 단정하지 말 것.

**최종 교훈:** 이번 세션에서 발견된 왜곡 버그는 하나의 원인이 아니라 **레이어별로 서로 다른 4가지 문제**가 겹쳐 있었다 — (14) IK Pole 불안정, (15) IK 다중해 모호성 + 웨이트 미정규화, (16) 미러링된 본 위치 오차, (17) 자동 웨이트 자체의 부분적 완전 누락. "증상이 비슷하면 원인도 하나"라고 가정하지 말고, 매번 **레스트 포즈 전체 메쉬 변형량**과 **웨이트 합=1.0 여부**와 **웨이트-0 고아 버텍스 유무**를 처음부터 끝까지 전수 검증하는 것이 가장 빠르고 확실한 진단 경로였다.

## 18. 걷기 애니메이션 팔-다리 좌우 매칭 반대 문제 (2026-08-18, 완료)

사용자 리포트: "오른쪽 다리가 움직일 때 왼쪽 팔들이 움직여야 하는데 반대로 동작한다" (자연스러운 보행은 다리와 반대쪽 팔이 짝을 이뤄야 함 — contralateral gait).

**원인:** 걷기 애니메이션 제작 시(10번 섹션) 팔 스윙에 `Shoulder` 본을 월드 X축 기준으로 회전시키는 방식을 썼는데, 이때 팔의 "회전 각도 부호"가 다리의 "Y축 이동 부호"와 반대로 매핑됨. 그 결과 의도했던 위상차(같은 쪽 다리와 반대 위상)가 실제로는 **같은 쪽 팔이 같은 쪽 다리와 동시에 앞으로 나가는(ipsilateral)** 결과를 만들었음 — 회전 기반 애니메이션은 이동 기반 애니메이션과 "양수=앞으로"가 자동으로 대응되지 않는다는 것을 놓침.

**조치:**
1. [x] 프레임별로 다리(FootIK)와 팔(Hand) 월드 Y좌표를 직접 측정해서 실제 앞/뒤 관계 확인 → 오른쪽 다리 앞 + 오른쪽 팔 앞(동측)으로 확인됨, 리포트 사실 확인
2. [x] 팔 스윙 위상을 다리와 반대쪽으로 맞바꿔서(`Upper.R`↔`Upper.L`, `Lower.R`↔`Lower.L`) 재키프레임
3. [x] 재측정: 오른쪽 다리 앞일 때 왼쪽 팔이 앞으로, 왼쪽 다리 앞일 때 오른쪽 팔이 앞으로 감을 확인 (Upper/Lower 팔 모두)
4. [x] `Monster_Rigged.fbx`, `Monster_Rigged_Walk.fbx` 재내보내기 및 재-임포트로 반대측 매칭이 실제 FBX에도 반영됨을 검증

## 1. 개요
- 대상 오브젝트: `Mesh_0` (버텍스 7,031 / 폴리곤 10,440, 머티리얼 1개)
- 참고 자료: `괴물 T-pose.png`
- 현재 씬에는 아마추어(Armature)가 없음 → 신규 생성 필요
- 작업 범위: **몸통/다리/머리는 제외**, 아래 6개 부위만 리깅
  - 일반 팔 4개 (위쪽 한 쌍 + 아래쪽 한 쌍): 어깨-팔꿈치-손목-손가락
  - 촉수 팔 2개 (뒤통수에서 뻗어나온 관 형태): 손가락 없음, **당기면 원래 길이의 최대 2배까지 신축**

## 2. 참고 이미지 분석
- 몸통 좌우에 클로(claw) 손을 가진 팔이 총 4개: 어깨/목깃 높이에서 뻗은 위쪽 팔 한 쌍(L/R), 몸통 옆구리에서 뻗은 아래쪽 팔 한 쌍(L/R). 각 손은 관절이 있는 손가락(claw) 여러 개로 구성.
- 머리 뒤쪽에서 이어지는 벨로우즈(주름진 호스) 형태의 촉수 2개(L/R)가 위로 굽어 올라가 끝에는 뭉게구름/뇌 모양의 뭉툭한 블롭으로 마무리 — 손가락 없음.
- 좌우 대칭 구조이므로 본(bone) 배치는 X축 미러로 절반만 작업 후 대칭 복사 가능.
- 정확한 손가락 개수(클로 개수)는 렌더 이미지만으로 확정하기 어려우므로, 실제 작업 착수 전 `Mesh_0`의 손 부위 버텍스 그룹/토폴로지를 근접 확인하여 확정한다 (예상 3~4개/손).

## 3. 아마추어 전체 구조 (계층도)

```
Armature
└ Root
   └ Spine_Root      (골반~복부 중심, 팔 리깅의 부모 역할만 함)
      └ Chest         (목깃 높이)
         ├─ Shoulder.Upper.L → UpperArm.Upper.L → Forearm.Upper.L(elbow) → Hand.Upper.L(wrist) → Finger.Upper.L.01~0n
         ├─ Shoulder.Upper.R → UpperArm.Upper.R → Forearm.Upper.R(elbow) → Hand.Upper.R(wrist) → Finger.Upper.R.01~0n
         ├─ Shoulder.Lower.L → UpperArm.Lower.L → Forearm.Lower.L(elbow) → Hand.Lower.L(wrist) → Finger.Lower.L.01~0n
         ├─ Shoulder.Lower.R → UpperArm.Lower.R → Forearm.Lower.R(elbow) → Hand.Lower.R(wrist) → Finger.Lower.R.01~0n
         └─ Head
            ├─ TentacleRoot.L → Tentacle.L.01 → Tentacle.L.02 → … → Tentacle.L.0n → TentacleTip.L (control)
            └─ TentacleRoot.R → Tentacle.R.01 → Tentacle.R.02 → … → Tentacle.R.0n → TentacleTip.R (control)
```

- `Root` / `Spine_Root` / `Chest` / `Head`는 이번 스코프(팔·촉수)의 상위 부모 본으로만 배치하며, 몸통 자체에 디폼 가중치는 주지 않는다 (요청 범위 밖).

## 4. 본 네이밍 규칙
- 좌/우 접미사: `.L`, `.R` (Blender 자동 미러 인식 규칙 준수)
- 팔 그룹 구분: `Upper`(위쪽 팔 쌍) / `Lower`(아래쪽 팔 쌍)
- 관절: `Shoulder → UpperArm → Forearm(팔꿈치) → Hand(손목) → Finger.0n(손가락)`
- 촉수: `TentacleRoot → Tentacle.0n(세그먼트) → TentacleTip(신축 컨트롤러)`

## 5. 일반 팔 4개 리깅 (손목 / 팔꿈치 / 손가락)
1. 이미지 기준 각 팔의 관절 위치(어깨/팔꿈치/손목)를 3D 뷰포트에서 확인 후 Edit Bone으로 배치. 팔꿈치 굽힘 방향이 명확히 보이도록 Y축 롤(roll) 값을 손등/손바닥 방향에 맞춰 조정.
2. 손마다 `Finger.0n` 본을 실제 클로 개수만큼 생성 (2 seg 정도의 짧은 체인이면 충분, 필요 시 손가락당 1~2 관절).
3. 회전 방식: 기본은 FK. 팔꿈치에 자연스러운 굽힘감이 필요하면 `Forearm`에 IK 체인(폴 타겟은 팔꿈치 바깥쪽에 배치) 추가를 옵션으로 고려 — 우선 FK로 구현 후 필요 시 확장.
4. 본 방향은 어깨→손끝으로 향하게 하고, `Connected` 옵션으로 체인을 이어 붙여 팔꿈치/손목 굽힘이 자연스럽게 보이도록 함.
5. 4개 팔은 좌우/상하 대칭이므로 `Upper.L` 한 쪽만 정밀 배치한 뒤 X-Mirror(Symmetrize)로 `Upper.R` 생성, `Lower.L`도 별도로 정밀 배치 후 미러.

## 6. 촉수 팔 2개 리깅 (2배 신축)
### 6.1 세그먼트 분할
- 벨로우즈(주름) 형상이 육안으로 5~7개 마디로 보이므로, 마디 수에 맞춰 `Tentacle.L/R.01~0n` 본을 촉수 곡선을 따라 배치 (곡선을 따라가도록 각 세그먼트를 짧게 나눔).
- 끝의 블롭(손 없는 뭉툭한 덩어리)은 `TentacleTip`이 디폼을 담당.

### 6.2 신축(당기면 2배) 메커니즘
- 방식: **Stretch-To 체인 + Limit Scale 클램프**
  1. 각 `Tentacle.0n` 본에 `Stretch To` 컨스트레인트를 걸어 타겟을 다음 본의 헤드(마지막은 `TentacleTip`)로 지정. Volume Preserve는 `None` (부피 보존 시 당길수록 얇아지는 비현실적 왜곡 방지, 또는 필요 시 소량만 적용).
  2. 각 본에 `Limit Scale` 컨스트레인트를 추가하여 로컬 Y(본 길이 방향) 스케일을 **최소 1.0 ~ 최대 2.0**으로 하드 클램프. → `TentacleTip`을 아무리 멀리 옮겨도 전체 촉수는 원래 길이의 정확히 2배에서 더 늘어나지 않음.
  3. `TentacleTip`은 애니메이터가 직접 옮기는 컨트롤 본(디폼 없음, IK 타겟 역할)으로 별도 커스텀 모양(빈 구체 등) 지정.
- 대안(2안): `Spline IK` (커브 기반) — 곡선을 더 부드럽게 유지해야 할 경우, 커브 오브젝트 + Spline IK 컨스트레인트(`Y Scale Mode: Bone Original`, `XZ Scale Mode: Volume Preservation`)를 사용하고 커브 컨트롤 포인트 이동 범위를 2배 길이 이내로 제한. 1안 대비 구현/디버깅이 복잡하므로 1안 우선 적용, 결과가 부자연스러울 때만 전환.
- 검증용 커스텀 프로퍼티: `TentacleTip`에 `Stretch_Amount` (0.0~1.0) 슬라이더를 추가해 Limit Scale과 별개로 애니메이터가 수치로도 신축을 제어할 수 있게 드라이버 연결 (옵션, 우선순위 낮음).

## 7. 스키닝(웨이트 페인팅) 전략
1. 아마추어를 `Mesh_0`의 부모로 지정하고 `Armature Deform: With Automatic Weights`로 1차 자동 웨이트 생성.
2. 관절부(팔꿈치, 손목, 촉수 마디 사이)에서 자동 웨이트가 매끄럽지 않은 구간을 Weight Paint 모드에서 수동 보정.
3. 촉수는 마디가 촘촘하므로 인접 세그먼트 간 웨이트가 50:50으로 부드럽게 블렌딩되도록 확인 (딱딱한 경계 방지).
4. 몸통/머리/다리 등 스코프 밖 정점은 어떤 팔/촉수 본에도 가중치가 섞여 들어가지 않도록 격리 확인.

## 8. 검증 절차
- 포즈 모드에서 각 팔의 `Shoulder → Forearm → Hand → Finger`를 회전시켜 관절부 메쉬 찢어짐/꺾임 여부 확인.
- `TentacleTip.L/R`을 원래 위치에서 멀리 이동시켜 촉수가 정확히 **2배 길이에서 멈추는지** 수치로 확인 (본 길이 합 측정).
- `TentacleTip`을 원위치로 되돌렸을 때 신축이 원래 길이로 정확히 복귀하는지 확인.
- 4팔 + 촉수 2개를 동시에 극단적으로 포즈했을 때 몸통/목/머리 메쉬가 함께 딸려가지 않는지 확인.
